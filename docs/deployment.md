# Deployment and public URLs

Sanket ISL Translator has not been deployed. The GitHub repository currently has no homepage URL. The website URL remains unset in `project.json`; no domain, demo URL or successful deployment is implied.

## Build the public site

Choose an HTTPS origin you control and set the environment variable `SITE_URL` to that origin, with no path component. Then run these commands from `frontend/`:

```bash
npm ci
npm run build:production
npm run check:discoverability
```

The production command refuses to build without a canonical origin. A normal `npm run build` without one creates an unpublished preview: HTML has `noindex, follow`, canonical and `og:url` fields are omitted, and the sitemap has no entries. Never publish that preview expecting indexing.

The `frontend/dist/` directory is the complete static website. Deploy only this directory, never the repository root. The explicit asset allowlist includes the classifier model, its label map, favicon, social image and generated documentation. It excludes training datasets, archive backups, local credentials and unreviewed demo footage. Model redistribution rights still require maintainer review because no project/model license was established.

## Hosting configuration

A Netlify configuration is supplied as one deployment option; it does not mean this project is already hosted there. Set `SITE_URL` to the permanent production origin in the hosting environment. The Netlify build uses the production gate only in its production context; preview contexts build without a canonical URL and remain noindex. Connect the repository only after publishing these changes and reviewing the source/model/media licensing.

Other static hosts can serve the same output. Serve directory indexes (`/docs/model/index.html`) at clean directory URLs (`/docs/model/`), redirect `/docs/model` and `/docs/model/index.html` to `/docs/model/`, and return a real 404 for unknown paths. Do not add a catch-all SPA rewrite: every documentation route has its own HTML. Keep the selected trailing-slash convention across canonical tags, links and sitemap entries. The generated `_redirects` file handles explicit index aliases on Netlify.

## Public paths generated at build time

The build emits `/`, `/about/`, `/docs/` and the documented `/docs/<topic>/` pages. Every technical page has a Markdown alternative at `/docs/<topic>/index.md` and links to `/llms.txt`. The site root receives `/llms.txt`, `/llms-full.txt`, `/robots.txt`, `/sitemap.xml`, `/project.json`, `/social-preview.png` and `/favicon.svg`.

These are actual files in the deployment output, generated by `frontend/scripts/discoverability.mjs`; a repository-root Markdown file is not mistaken for a deployed resource. Repository maintenance documents are excluded from public output.

## Interactive translator dependencies

The static app performs browser recognition, but English sentence assembly still posts to the visitor's `http://localhost:3001/api/assemble`. It requires their local Express/Ollama setup, and browser policies may limit public-to-local requests. A public site is not a shared hosted translation service. Deploying a remote API would require a separate decision about endpoint configuration, access control, abuse limits and processing privacy. No backend service is deployed by this static configuration.

Camera access requires a secure context, such as HTTPS or localhost. MediaPipe assets and application fonts load from external hosts. Demo footage is not included in production; local development keeps existing videos available.

## After publishing

Verify each sitemap URL returns meaningful HTML without JavaScript, then confirm canonical redirects, social image, MIME types, `robots.txt` and both llms files. Add the verified production origin to `project.json`, GitHub's website field and the README. Rebuild if the origin changes. Register the origin with Google Search Console and Bing Webmaster Tools, verify ownership, submit the sitemap and inspect representative pages. Account ownership and submission credentials are not part of this repository.

Search engines have independent indexing systems; AI retrieval systems differ and not all consume llms.txt. Indexing may take time and neither ranking nor citation is guaranteed. Legitimate external technical references help establish identity; they must not be fabricated.
